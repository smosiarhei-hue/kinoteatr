# Kinoteatr (Fluxo) — план починки воспроизведения фильмов

Дата: 2026-08-24. Статус: правки внесены, нужна сборка CI/Xcode и проверка на устройстве.

## 1. Почему фильмы не запускались — диагноз

Найдено 4 причины (по коду):

1. **Демо-режим: гонка порта HTTP-сервера.** `LocalHTTPServer` стартует с портом 0 (эфемерный),
   а URL строился сразу после `start()`. NWListener мог ещё не назначить порт, и плеер получал
   адрес вида `http://127.0.0.1:0/...` — ничего не открывалось.
   → Исправлено: перед возвратом URL ждём, пока сервер получит реальный порт.

2. **Конфигурация: TorrServer задан, Jackett пуст → список провайдеров пуст.**
   `MagnetSearchService` добавляет демо-провайдера только когда TorrServer не настроен, а Jackett
   берётся только из настроек. Итог: настроили TorrServer, забыли Jackett — поиск возвращает
   ничего и фильм «не запускается».
   → Исправлено: отдельный экран «Не настроен поиск раздач» с подсказкой, что делать.

3. **Ошибки плеера были «немыми».** При сбое AVPlayer (недоступный поток, 404, нет сидов)
   пользователь видел чёрный/зависший экран без сообщения.
   → Исправлено: следим за `AVPlayerItem.status` и показываем понятную ошибку с причиной.

4. **TorrServer с паролем не поддерживался.** Все запросы шли без `password` — сервер отклонял.
   → Исправлено: поле «Пароль TorrServer» в настройках, пароль передаётся во все запросы.

Дополнительно починили:
- невалидный URL TorrServer ронял приложение (force unwrap) — теперь понятная ошибка;
- если TorrServer не вернул список файлов раздачи — ошибка «metadataTimeout», а не стрим «в никуда»;
- в консоль добавлен лог HTTP-статуса Jackett — проще диагностировать.

## 3. Настройка — варианты

**Вариант A. Полный (TorrServer + Jackett)**
1. TorrServer на ПК, телефон и ПК в одной Wi-Fi сети. Открыть `http://<ip-пк>:8090` — UI доступен?
2. Если на TorrServer задан пароль — указать его в приложении: Настройки → Режим разработчика → «Пароль TorrServer».
3. Jackett на ПК (`http://<ip-пк>:9117`), скопировать полный URL раздела «Copy results API URL» (All Indexers): например
   `http://192.168.1.10:9117/api/v2.0/indexers/all/results?apikey=XXXX` — вставить в приложение.
4. Проверка в браузере ПК: `.../results?apikey=XXXX&Query=Inception` — должен вернуться JSON со списком Results.
5. В приложении: фильм → выбрать раздачу (бейджи: качество / озвучка / сиды) → смотреть.

**Вариант B. Демо без серверов (проверка, что плеер вообще работает)**
- Очистить поля Jackett и TorrServer. При выборе фильма появится демо-раздача, проигрывается
  сгенерированный ролик через локальный HTTP-сервер. Если и демо не играет — проблема в самом
  воспроизведении (раздел 5).

## 4. Сборка и установка
- macOS: `xcodegen generate` → открыть `Kinoteatr.xcodeproj` → Run на устройство (iOS 17+).
- CI: `git push` → GitHub Actions соберёт `unsigned` и `signed` IPA → артефакты → установка через GBox/eSign (side-load). Версия автоинкрементируется.
- На Windows собрать нельзя (нужен Xcode). Сборку подтверждает CI.

## 5. Если всё ещё не играет — диагностика
1. Консоль Xcode: искать `[MagnetSearch] Jackett: HTTP ...` и сообщения об ошибках плеера (теперь они видны и на экране).
2. TorrServer UI → Torrents: раздача добавлена? `stat` растёт (0 → качается → готово)? Если висит без метаданных/сидов — у magnet нет трекеров; выбрать раздачу с большим числом сидов или добавить трекеры в magnet.
3. Jackett: открыть URL из настроек в браузере. 401/403/404 → неверный apikey/порт.
4. Сеть: VPN на телефоне выключить (блокирует LAN); на первый запрос iOS спросит разрешение «Локальная сеть» — разрешить.

## 6. Известные ограничения
- App Store Review приложение не пройдёт (торрент-стриминг) — только side-load (GBox/eSign).
- Воспроизведение нелицензионного контента — отдельный правовой риск.
- TMDB API-ключ захардкожен (Settings.swift) — рекомендуется ротировать в TMDB dashboard и вынести на свой прокси-сервер.

## 8. Дополнение: фикс сборки в CI (2026-08-24, вечер)

Выяснилось, что **CI падал ещё до правок воспроизведения**: последние сборки (20.08 и 24.08)
завершались ошибкой компиляции

`OrientationManager.swift:19:79: error: argument passed to call that takes no arguments`.

Причина: раннер использует Xcode 26.3 / SDK iPhoneOS 26.2, где
`requestGeometryUpdate(.iOS(interfaceOrientation: ...))` больше не компилируется
(член `.iOS` не принимает аргументов). Это сломало сборку после добавления автоповорота.

Исправлено: `OrientationManager` переписан на совместимый со всеми SDK способ —
маска `supportedInterfaceOrientationsFor` через AppDelegate + принудительный поворот
через `UIDevice setValue("orientation")` с проверкой `responds(to:)` (без падения
на будущих iOS, если приватный селектор уберут). Сборка снова должна проходить.
